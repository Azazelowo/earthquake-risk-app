# 人因與使用介面檢查（2026-11-21）

> 依據：(1) 外部使用評估報告《臺灣地震風險評估 App｜網站使用回饋》（2026-11-20～21，窄版瀏覽器實測、未看原始碼）；
> (2) 我們自己對照 Nielsen 十項使用性原則、WCAG 2.2 的基本項目、風險溝通原則逐頁檢查；
> (3) 375 px 手機寬度、深色與淺色、字級放大到 130% 的實際畫面。

## 為什麼要做

這個 APP 給一般人看機率。數字本身算對還不夠：**使用者讀到的意思**要和數字一致。風險溝通最怕兩件事——
把「低於平常」讀成「跟平常一樣」或「很安全」，以及把「高一點」讀成「地震快來了」。
另外使用者明確要求「不用自己調排版」：字級、深淺色應該跟著手機設定走。

## 原則（之後改介面時照這幾條）

1. **數字和文字說同一件事**：任何「約 X 倍」都必須是實際值四捨五入，不為了好看而改寫。
2. **顏色之外一定有文字**：狀態、圖例都要有文字標籤（色弱、黑白列印都看得懂）。
3. **不說「安全」**、不用綠色：低於平常也要寫明「不代表比較安全」。
4. **時間要分清楚**：「更新時間」（多久前重算）和「資料時間」（目錄到哪一天）分開寫。
5. **使用者不用調設定**：字級、深淺色、動態效果都跟系統；版面在 375 px 和 130% 字級下不能溢出。
6. **提醒不放首頁醒目處**（11/15 的決定），但資料時間這類事實可以用淡色一行字放在主數字旁。
